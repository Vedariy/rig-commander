🚀 1. Быстрый старт и режимы работы1. Quick Start & Discovery Modes

0 NPM DEPS • NODE ≥ 18

RigCommander — локальный сервер без облачных аккаунтов и без внешних npm-зависимостей. Запускается одной командой и сразу открывает живой пульт на http://127.0.0.1:7440. RigCommander is a zero-dependency, local-first server with no cloud login. One command starts the live bridge and opens http://127.0.0.1:7440.

npx rig-commander@latest
🧠 Режим 1: OpenRig (автоматически)Mode 1: OpenRig Native (Automatic)

Если запущен rig daemon (:7437), RigCommander автоматически читает топологию ригов, живую очередь конвертов, журнал решений decisions/*.tsv, припаркованные узлы, сводки recap и живые экраны tmux каждые 4 секунды. When rig daemon (:7437) is running, RigCommander reads rig topology, live queue envelopes, decisions/*.tsv, parked obligations, recaps, and live tmux screens every 4 seconds.

🌐 Режим 2: Universal (без OpenRig)Mode 2: Universal Mode (No OpenRig Needed)

Если OpenRig не запущен (или передан флаг --universal), пульт сам сканирует локальные tmux-панели с Claude Code / Codex / Aider / Gemini и инкрементально читает JSONL-транскрипты в ~/.claude/ и ~/.codex/. If OpenRig is absent (or you pass --universal), RigCommander automatically discovers local tmux panes running Claude Code / Codex / Aider / Gemini and tails JSONL transcripts in ~/.claude/ and ~/.codex/.

DARK COCKPIT • SA-DSS

Интерфейс построен по авиационному принципу Dark Cockpit: пока всё работает штатно — экран спокойный; внимание притягивают только реальные блокеры и перегрев. У каждого из 9 виджетов справа вверху есть иконка (?) с быстрым пояснением. The deck follows aviation Dark Cockpit ergonomics: healthy seats stay quiet while true blockers and context overheating stand out. Every widget also includes a top-right (?) hint popover.

❓ 8. Частые вопросы и диагностика8. FAQ & Troubleshooting

TROUBLESHOOTING
Почему граф иногда показывает «ДЕМО-ПЕСОЧНИЦА» вместо моих агентов?Why does the badge say "DEMO SANDBOX" instead of my live agents?

Это значит, что локальный rig daemon :7437 не отдал живых узлов и в tmux / ~/.claude / ~/.codex не нашлось активных сессий. Запустите OpenRig или хотя бы одного агента в tmux (либо запустите npx rig-commander --universal) — пульт переключится на живые данные автоматически через 4 секунды. Either local rig daemon :7437 returned 0 running nodes and no active tmux / ~/.claude / ~/.codex sessions were detected. Start your rig or launch an agent in tmux (or pass --universal) — the deck switches to live telemetry automatically on the next 4s poll.

Почему агент в терминале висит на вопросе, а сам OpenRig считает, что он «работает»?Why does OpenRig think an agent is "working" when it is actually waiting on a prompt?

Некоторые терминальные харнесы (например, Antigravity / Gemini CLI) держат живой PTY без структурированного события ожидания. RigCommander решает это отдельным классификатором экранов classifyTerminalScreen(): он каждые 2.5с анализирует 72 строки живого tmux, отличает активные спиннеры Брайля от реального HITL-меню и переводит узел в needs-input (или в shellExited, если процесс вышел в shell). Terminal runtimes (e.g. Antigravity / Gemini CLI) keep the PTY alive without structured wait hooks. RigCommander runs classifyTerminalScreen() on 72-line live tmux captures every 2.5s to distinguish active Braille spinners from real confirmation menus and bare shell exits.

Граф стал тусклым или пропала часть узлов — куда они делись?Why did graph nodes become dimmed or hidden?

Проверьте три переключателя в HUD: (1) выбран ли фильтр СРЕЗ (нажмите ВСЕ ПОТОКИ), (2) включён ли CALM: ON (приглушает здоровые узлы, оставляя фокус на аномалиях), (3) нажата ли кнопка СПЯЩИЕ: СКРЫТЫ (рядом с ней внизу графа всегда есть быстрая кнопка «Показать»). Check three HUD toggles: (1) active SLICE filter (click ALL FLOWS), (2) CALM: ON (dims healthy nodes to highlight anomalies), or (3) IDLE: HIDDEN (click "Show" in the bottom-left graph pill).

Где хранятся настройки UI и сессии привязанных телефонов?Where are UI preferences and paired phone sessions stored?

Настройки интерфейса (язык, выбранный риг, CALM, плотность, панели) хранятся локально в localStorage браузера. Хэши привязанных телефонов и сохранённый HTTPS-URL хранятся локально на вашем Mac в ~/.config/rig-commander/remote-sessions.json с правами 0600. Никакие данные никуда не отправляются. UI preferences (language, rig filter, CALM, density, panels) stay in browser localStorage. Paired phone SHA-256 session hashes and your configured HTTPS origin are stored strictly locally in ~/.config/rig-commander/remote-sessions.json (mode 0600). Nothing is sent to external servers.

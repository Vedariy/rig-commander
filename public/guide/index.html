🚀 1. Быстрый старт и режимы работы1. Quick Start & Discovery Modes

0 NPM DEPS • NODE ≥ 18

RigCommander — локальный сервер без облачных аккаунтов и без внешних npm-зависимостей. Запускается одной командой и сразу открывает живой пульт на http://127.0.0.1:7440. RigCommander is a zero-dependency, local-first server with no cloud login. One command starts the live bridge and opens http://127.0.0.1:7440.

npx rig-commander@latest
🧠 Режим 1: OpenRig (автоматически)Mode 1: OpenRig Native (Automatic)

Если запущен rig daemon (:7437), RigCommander автоматически читает топологию ригов, живую очередь конвертов, журнал решений decisions/*.tsv, припаркованные узлы, сводки recap и живые экраны tmux каждые 4 секунды. When rig daemon (:7437) is running, RigCommander reads rig topology, live queue envelopes, decisions/*.tsv, parked obligations, recaps, and live tmux screens every 4 seconds.

🌐 Режим 2: Universal (без OpenRig)Mode 2: Universal Mode (No OpenRig Needed)

Если OpenRig не запущен (или передан флаг --universal), пульт сам сканирует локальные tmux-панели с Claude Code / Codex / Aider / Gemini и инкрементально читает JSONL-транскрипты в ~/.claude/ и ~/.codex/. If OpenRig is absent (or you pass --universal), RigCommander automatically discovers local tmux panes running Claude Code / Codex / Aider / Gemini and tails JSONL transcripts in ~/.claude/ and ~/.codex/.

🗺️ 2. Как читать пульт за 5 секунд (уровни L0 → L3)2. Reading the Deck in 5 Seconds (SA-DSS L0 → L3)

DARK COCKPIT • SA-DSS

Интерфейс построен по авиационному принципу Dark Cockpit: пока всё работает штатно — экран спокойный; внимание притягивают только реальные блокеры и перегрев. У каждого из 9 виджетов справа вверху есть иконка (?) с быстрым пояснением. The deck follows aviation Dark Cockpit ergonomics: healthy seats stay quiet while true blockers and context overheating stand out. Every widget also includes a top-right (?) hint popover.

L0 · Верхняя полоса триажа (Triage Strip)Top Triage Strip

Что смотреть первым: общий бейдж здоровья (ЗДОРОВЬЕ: 85% — открывает отдельный План действий) и до 3 диверсифицированных ситуаций (HITL, контекст ≥ 75%, реальные заторы очереди). Справа — Советник флота (4 вкладки аналитики), Авто-тормоз / TG, Карточка дня, QR на телефон, автообновление ⬆ Update, Гайд, Паспорт и EN/RU. Check first: fleet HEALTH % (opens the focused Health & Action Plan) and Top-3 seat-diverse alerts (HITL prompts, context ≥ 75%, real queue bottlenecks). Quick buttons open Fleet Advisor (4 analytical tabs), Guardrails / TG, Share Card, Phone QR, ⬆ Update, Guide, Passport, and EN/RU.

L1 · Пулы моделей, Граф (Динам/Фикс) и Гант + ПередачиModel Pools, Adaptive Graph & Task Gantt + Handoff Flow

Граф магистралей поддерживает 2 режима прямо в шапке: Динам (активные на верхней сцене, спящие — компактной скамьёй внизу) и Фикс (стабильные ролевые ярусы). По клавише G открывается Операционный Гант: поддорожки без наложений, По агентам / По слайсам, хронологический Handoff Flow, KPI ожидания и фильтр шума. Call Highways Graph has a header toggle for Dynamic (active seats on the upper stage, sleepers docked as compact pills below) vs Fixed (stable role tiers). Press G for the Operational Task Gantt: non-overlapping sub-lanes, By Agent / By Slice, chronological Handoff Flow, Wait-vs-Work KPIs, and noise filtering.

L2 · Радар ожиданий и Рентген магистралиWait Radar & Route X-Ray

Слева — Радар ожиданий (Кто → Кого → Зачем ждёт) с вкладками Все / Блокеры / Задачи и Журналом решений. Клик по любой линии на графе открывает Рентген магистрали — конверты сгруппированы по задачам; клик по конверту с несколькими событиями разворачивает хронологию с временными метками. Left panel is Wait Radar (Who → Whom → Why) with All / Blockers / Tasks tabs and Decisions Log. Clicking any graph highway opens Route X-Ray: envelopes grouped by task, clickable to expand timestamped round history.

L3 · Паспорт узла, Диагноз, Live TMUX и АудитNode Passport, Diagnosis, Live TMUX & Audit

Справа — выбранный агент: в самом верху блок Диагноз и что исправить (точные ожидающие задачи и кнопка 📨 Разобрать очередь), потоковый 80-строчный экран tmux (SSE + AUTO-FOLLOW), распарсенные кнопки ответа с защитой от двойного клика, журнал Action Audit и Рейтинг возвратов QA. Right panel shows the selected seat: top Diagnosis & What to Fix card (exact pending queue items + 1-click 📨 Process queue), live SSE-streamed 80-line tmux capture (AUTO-FOLLOW), idempotency-guarded prompt pills, postcondition-verified Action Audit, and QA Rework Scorecard.

Почему граф иногда показывает «ДЕМО-ПЕСОЧНИЦА» вместо моих агентов?Why does the badge say "DEMO SANDBOX" instead of my live agents?

Запустите OpenRig или хотя бы одного агента в tmux (либо запустите npx rig-commander --universal) — пульт переключится на живые данные автоматически через 4 секунды. Start your rig or launch an agent in tmux (or pass --universal) — the deck switches to live telemetry automatically on the next 4s poll.

Почему агент в терминале висит на вопросе, а сам OpenRig считает, что он «работает»?Why does OpenRig think an agent is "working" when it is actually waiting on a prompt?

Некоторые терминальные харнесы (например, Antigravity / Gemini CLI) держат живой PTY без структурированного события ожидания. RigCommander решает это встроенным живым классификатором экранов терминала: он анализирует вывод tmux в реальном времени, отличает активные спиннеры от реального меню подтверждения и автоматически переводит узел в ожидание ввода (или помечает выход в shell). Terminal runtimes (e.g. Antigravity / Gemini CLI) keep the PTY alive without structured wait hooks. RigCommander runs a live terminal state classifier over tmux output to distinguish active work spinners from real confirmation menus and bare shell exits.

Граф стал тусклым или пропала часть узлов — куда они делись?Why did graph nodes become dimmed or hidden?

Проверьте три переключателя в HUD: (1) выбран ли фильтр СРЕЗ (нажмите ВСЕ ПОТОКИ), (2) включён ли CALM: ON (приглушает здоровые узлы, оставляя фокус на аномалиях), (3) нажата ли кнопка СПЯЩИЕ: СКРЫТЫ (рядом с ней внизу графа всегда есть быстрая кнопка «Показать»). Check three HUD toggles: (1) active SLICE filter (click ALL FLOWS), (2) CALM: ON (dims healthy nodes to highlight anomalies), or (3) IDLE: HIDDEN (click "Show" in the bottom-left graph pill).

Где хранятся настройки UI и сессии привязанных телефонов?Where are UI preferences and paired phone sessions stored?

Настройки интерфейса (язык, выбранный риг, CALM, плотность, панели) хранятся локально в localStorage браузера. Хэши привязанных телефонов и сохранённый HTTPS-URL хранятся локально на вашем Mac в ~/.config/rig-commander/remote-sessions.json с правами 0600. Никакие данные никуда не отправляются. UI preferences (language, rig filter, CALM, density, panels) stay in browser localStorage. 10 нестандартных и продвинутых флоу OpenRig 10 Advanced OpenRig Operational Flows

1–3. Усыновление живых tmux-агентов (discover/adopt), attach --self и горячее масштабирование (grow/expand)1–3. Adopt running tmux agents (discover/adopt), attach --self, and live scaling (grow/expand)
rig discover --draft && rig adopt ./rig.yaml --bind dev.coder=<tmuxSession>
rig attach --self --rig <rigId> --pod operator --member person-agent --runtime codex --print-env
rig grow core-platform coder6 --pod dev --runtime codex --cwd /path/to/repo

rig release <rigId> отпускает adopted-сессии живыми, не убивая терминалы. attach --self включает ваш внешний shell в топологию, чтобы агенты могли делать handoff прямо в ваш инбокс, а grow/expand/add/remove масштабируют живой риг без rig down. rig release <rigId> detaches adopted sessions without killing terminals. attach --self registers your own shell as a named member so agents can hand off directly to your inbox, while grow/expand/add/remove scale a live rig without rig down.

4–6. Пересадка рантайма (set-runtime), клон прогретого агента (fork) и защита контекста (compact/watchdog/handover)4–6. Live runtime transplant (set-runtime), warmed-agent cloning (fork), and context hygiene (compact/watchdog/handover)
rig seat set-runtime dev-coder4@core-platform --runtime claude-code --reason "quota swap" --dry-run
rig fork dev-coder4@core-platform --rig core-platform --pod dev --member coder4-spike --keep-image
rig compact dev-check@core-platform
rig handover dev-coder4@core-platform --source fork:dev-coder4@core-platform --reason "clean successor"

Successor-First: при set-runtime новый рантайм прогревается рядом с handover-пакетом, входящие сообщения придерживаются и не теряются. rig fork раздваивает агента с прогретым контекстом для параллельной гипотезы, а rig watchdog register --policy context-usage-threshold --threshold-percent 70 предупреждает до деградации. Successor-First: set-runtime boots the replacement runtime alongside the old seat with a handover pack while holding incoming work safely. rig fork clones a warmed agent to test parallel hypotheses, and rig watchdog register --policy context-usage-threshold --threshold-percent 70 alerts before context rot.

7–10. Некромантия одного вопроса (ask --wake), дозированный контекст (context+walk), ACP, мульти-хост и crash-cart7–10. One-question wake (ask --wake), paced context (context+walk), ACP, multi-host & crash-cart
rig ask core-platform "Why was this index chosen?" --wake dev-senior-architect@core-platform
rig context compose --out packs/onboarding --from ./ADR-01.md ./API.md
rig walk dev-coder5@core-platform --through packs/onboarding --pace 12s
rig acp run <qitemId> <agent-cmd> # emergency: rig crash-cart --json

ask --wake точечно будит архивное кресло на один вопрос и снова усыпляет. context + walk скармливает большие спеки порциями с паузами. Для пробивки застрявшего меню (после визуальной проверки экрана) используйте rig send <seat> "1" --dangerously-interact --reason "...", а когда демон не стартует — rig crash-cart --json. ask --wake wakes a stopped/archived seat for a single question and puts it back to sleep. context + walk feeds large specs in paced chunks. To answer a stuck menu (after checking the screen), use rig send <seat> "1" --dangerously-interact --reason "...", and when the daemon won't boot, run read-only rig crash-cart --json.

Топ-7 антипаттернов OpenRig: (1) ставить задачи через rig send вместо rig queue create; (2) передавать --no-nudge (оставит агента спать) или ждать от --force пробивки меню; (3) запускать rig broadcast без --rig/--pod («broadcast storm»); (4) класть многострочный текст с бэктиками в --body вместо --body-file; (5) путать rig down --delete и rig archive; (6) верить проекции rig ps вместо живого экрана rig capture и rig parked; (7) поднимать kernel без --existing или править SQLite вручную вместо rig seat clear-attention. Top 7 OpenRig Anti-Patterns: (1) assigning work via rig send instead of rig queue create; (2) passing --no-nudge (leaves agents asleep) or expecting --force to bypass prompts; (3) running rig broadcast without --rig/--pod (broadcast storm); (4) putting multiline backtick text in --body instead of --body-file; (5) confusing rig down --delete with rig archive; (6) trusting rig ps projections over live rig capture & rig parked; (7) starting kernel without --existing or hand-editing SQLite instead of rig seat clear-attention.

# ADR-0004: Безопасность локального командного интерфейса (`/api/send`)

- **Статус:** `[ACCEPTED]`
- **Дата:** 2026-11-05
- **Контекст:** Предотвращение межсайтовых атак (CSRF / Remote Command Execution) через локальный HTTP-сервер дашборда.

---

## 1. Контекст и проблема

Сервер `server.mjs` работает локально на порту `7440` и имеет эндпоинт `POST /api/send`, который исполняет команду `rig send <seat> <text>`. Этот вызов напрямую вводит текст в консоли агентов в `tmux`.

Если сервер не защищён:
- Вредоносная веб-страница, открытая пользователем в том же браузере, может отправить скрытый фоновый запрос `fetch('http://127.0.0.1:7440/api/send', { method: 'POST', body: ... })`;
- Атакующий может внедрить произвольные команды в терминал ведущего агента (`dev-owner`) от имени локального пользователя хоста.

## 2. Принятое решение

Внедрить строгую **эшелонированную защиту** командного интерфейса на уровне `server.mjs`:

1. **Строгая проверка заголовка `Origin`:**
   Сервер отвергает любые запросы к `/api/send`, если заголовок `Origin` отсутствует или не совпадает строго со списком доверенных локальных адресов:
   `http://127.0.0.1:7440` или `http://localhost:7440`. Любой сторонний сайт блокируется с кодом `403 Forbidden`.

2. **Одноразовый per-process токен (`X-Deck-Token`):**
   - При старте `server.mjs` генерируется криптографически стойкий случайный токен:
     `const DECK_TOKEN = crypto.randomBytes(24).toString('hex');`
   - При отдаче страницы `index.html` сервер динамически инжектирует токен в `<meta name="deck-token" content="...">`;
   - При отправке команд браузер считывает токен и передаёт его в заголовке `X-Deck-Token: ...`;
   - Сервер валидирует токен функцией с защитой от атак по времени: `crypto.timingSafeEqual(a, b)`.

3. **Отказ от wildcard CORS:**
   Заголовки `Access-Control-Allow-Origin: *` полностью удалены со всех эндпоинтов сервера.

4. **Валидация формата идентификатора сиденья:**
   Идентификатор сессии валидируется регулярным выражением `^[a-zA-Z0-9._@-]+$`, исключая инъекции аргументов в shell.

## 3. Последствия

### Плюсы:
- Полная невосприимчивость к CSRF и DNS-rebinding атакам;
- Сторонний сайт в браузере не может прочитать `<meta name="deck-token">` из-за Same-Origin Policy браузера, и соответственно не может авторизовать `POST /api/send`;
- Нулевые накладные расходы: токен генерируется в оперативной памяти сервера при запуске и не требует базы данных.

# ADR-0015: Палитра команд (⌘K) и безопасный триаж очереди

- **Статус:** `[ACCEPTED]`
- **Дата:** 2026-11-25
- **Связанные документы:** [ADR-0004](0004-secure-local-control-plane.md), [ADR-0010](0010-control-plane-idempotency-remote-pwa-and-self-update.md), [ADR-0014](0014-shift-catchup-digest-and-jsonl-history.md)

---

## 1. Контекст и проблема

Флот из 15–20 сидений в нескольких ригах и десятки открытых `qitem` превратили навигацию в «охоту мышью»: чтобы добраться до нужного агента, слайса на Ганте, вкладки Советника или ответить на HITL, оператор делал 3–5 кликов по разным панелям. Параллельно накапливались **зависшие передачи** — задачи, адресованные сиденью в `PARKED`, упавшему в OS shell, застрявшему на HITL или вовсе отсутствующему во флоте. Их приходилось выискивать вручную в `rig queue list`.

Главный риск автоматизации здесь — **деструктивность**: массовое «разбудить всех» или закрытие задач может привести к потере работы, дублирующим промптам и флуду в терминалах агентов.

---

## 2. Рассмотренные альтернативы

1. **Сторонние библиотеки палитр (`cmdk`, `ninja-keys`, `kbar`):**
   - *Минус:* нарушают `dependencies: {}` и Zero-Build (ADR-0001), требуют React/Lit.
2. **Кнопки массового триажа («Close stale», «Nudge all»):**
   - *Минус:* необратимые мутации очереди без контекста и N одинаковых промптов в один терминал.

---

## 3. Принятое решение

1. **Чистый zero-DOM доменный модуль (`openrig/assets/domain/command-palette.js`):**
   - `parsePaletteQuery` — префиксы скоупов: `>` действия, `@` сиденья, `#` триаж очереди, `/` виды.
   - `fuzzyScore` / `rankPaletteItems` — детерминированный fuzzy-поиск (префикс > граница слова > подстрока > разреженная подпоследовательность), multi-token AND, MRU-буст (`rigcommander_palette_recent_v1`) и приоритет критичности на пустом запросе.
   - `triageQueueItems` — классификация открытых передач: `destination_shell_exited` (P0), `destination_hitl` (P0), `orphan_destination` (P1), `destination_parked` (P1), `stale_pending` (>30 мин, P1/P2), `blocked_on` (P2), `stuck_in_progress` (>2 ч без обновлений, P2); дедупликация строк по `qitemId`.
   - `buildPaletteIndex` — единый индекс: ремедиации триажа, зависшие `qitem`, сиденья, HITL-экраны, `/compact` для горячих контекстов, находки Советника, слайсы Ганта и навигация по видам.

2. **Инварианты безопасности триажа:**
   - Триаж **никогда** не закрывает, не удаляет и не переназначает задачи очереди — только read-only навигация (`open_context`, `focus_seat`, `open_screen`, `clipboard`).
   - Единственное write-действие — существующий защищённый промпт `nudge_queue` (`rig queue list --owned`), **один на сиденье-адресата** вне зависимости от числа зависших задач; для сидений на HITL предлагается экран, для упавшего shell — копия `rig restart`, для отсутствующих адресатов — только просмотр.
   - Каждый элемент несёт `risk: 'read' | 'write'`; любое `write` требует **двухшагового подтверждения** (повторный `Enter` в течение 6 с, `Esc` — отмена) и уходит через существующий `ActionFlightGuard` + `X-Idempotency-Key` + `ActionAuditLog` (ADR-0010).

3. **UI (`index.html`, `deck.css`, `i18n.js`):** глобальный `⌘K` / `Ctrl+K` (работает и из полей ввода, учитывает RU-раскладку), кнопка `⌘K` с бейджем P0+P1 зависших передач, навигация `↑↓`, `↵` выполнить, `⇧↵` перейти к сиденью, `Tab` — смена скоупа, подсветка совпадений, группы результатов; демо-треки `/demo?track=palette` и `/demo?track=triage`.

---

## 4. Последствия

- **Плюсы:** любое действие деки за 1–2 нажатия клавиш; зависшие передачи видны сразу с конкретной безопасной ремедиацией; нулевые зависимости и 0 изменений серверного API (используются существующие `/api/telemetry`, `/api/send`, `/api/queue/item`).
- **Ограничения:** триаж опирается на поля `tsCreated/tsUpdated` и `pickup.state` из `rig queue list`; при их отсутствии классифицируются только состояния адресата (HITL / shell / parked / orphan).

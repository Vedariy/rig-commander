# ADR-0005: Динамический подхват актуальной топологии рига (Dynamic Discovery)

- **Статус:** `[ACCEPTED]`
- **Дата:** 2026-11-06
- **Контекст:** Автоматическая адаптация дашборда при добавлении, смене или удалении агентов в OpenRig без необходимости ручной правки исходного кода.

---

## 1. Контекст и проблема

Изначально список агентов в дашборде был статическим массивом из 8 узлов.
Когда в риг был добавлен новый агент (`dev-senior-architector@core-platform`), дашборд не отобразил его даже после перезагрузки страницы, так как цикл обновления содержал условие `if (!target) continue;`, отбрасывающее любые неизвестные узлы.

При живой разработке состав рига динамически меняется:
- Добавляются специализированные специалисты (например, старший архитектор, дежурный по релизу, перформанс-инженер);
- Узлы могут мигрировать между рантаймами (`codex`, `claude-code`, `agy`, `pi`);
- Возникают новые маршруты общения в очереди `rig queue`.

## 2. Принятое решение

Реализовать в `index.html` механизм **полностью динамического обнаружения узлов и связей**:

1. **Функция `ensureDynamicAgent(liveNode)`:**
   - Вызывается для каждого объекта из массива `data.nodes`, пришедшего от OpenRig daemon;
   - Фильтрует чисто инфраструктурные терминальные сессии без моделей (например, пустой `zsh` в `coder2` или служебный демон `queue-worker`);
   - Автоматически вычисляет смысловую роль и иконку узла по его `logicalId` и спецификации (`senior/architector` ➔ `📐 Старший Архитектор`, `coder` ➔ `💻 Кодер`, `check/qa` ➔ `🛡️ Доказательный QA`, `operator` ➔ `🧭 Оператор`);
   - Назначает базовые координаты яруса (Tier 1..4) с запуском алгоритма бесконфликтной расстановки:
     ```javascript
     while (AGENTS.some(a => Math.abs(a.x - defaultX) < 18 && Math.abs(a.y - defaultY) < 16)) {
       defaultX = (defaultX + 22) % 85;
       if (defaultX < 12) { defaultX = 14; defaultY = (defaultY + 16) % 80; }
     }
     ```
   - Добавляет зарегистрированный узел в глобальный реестр `AGENTS`.

2. **Функция `ensureEdge(from, to, calls, slice)`:**
   - Автоматически строит векторные магистрали вызовов между любыми взаимодействующими агентами, обнаруженными в `data.history.pairCounts` или открытых строках `data.activeQueue`.

3. **Динамический расчёт пулов ресурсов:**
   - Список агентов в Card 1 (`CODEX SOL`) отвязан от жёсткого перечня ID и вычисляется динамическим фильтром по семейству рантайма/модели.

## 3. Последствия

### Плюсы:
- Любой добавленный в OpenRig агент (`rig add` или `rig grow`) автоматически материализуется на карте дашборда при очередном тике телеметрии (в течение 4 секунд);
- Никаких наложений карточек друг на друга благодаря геометрическому контролю минимальных дистанций;
- Вся живая телеметрия (контекст, tmux, очередь, статус) сразу доступна в паспорте узла.

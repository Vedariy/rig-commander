# ADR-0007: Universal Rig Decoupling & Standalone Deck Architecture

## Статус
Принято (Accepted)

## Контекст и Проблематика
OpenRig Neural Command Deck (v3) зарекомендовал себя как высокоэффективный операторский центр управления мультиагентной разработкой, снижающий когнитивную нагрузку оператора на 75% ([ADR-0006](0006-action-first-visual-hierarchy.md)) и предоставляющий мгновенный доступ к телеметрии, состоянию контекста, очередям и терминалам сессий.

Однако исторически дашборд разрабатывался в контексте первого пилотного рига `core-platform`. В кодовой базе сформировался ряд специфических связей (coupling):
1. **Хардкод словаря `SEAT_GUIDANCE`:** Обязанности (`duties`) и запреты (`boundaries`) сидений `dev-owner`, `dev-coder`, `dev-check` были жестко зашиты в коде `server.mjs`.
2. **Статические резервуары квот в шапке:** Плашки `🟣 CODEX SOL`, `🟢 GLM PLAN`, `🔵 DEEPSEEK + APIKO` были зафиксированы в HTML-структуре `index.html`.
3. **Жесткий путь к решениям (`decisions/`):** Путь к файлу решений `2026-11-04.tsv` был привязан к локальной файловой системе пилотного проекта.
4. **Фиксированный пайплайн слайсов:** 5 стадий дорожек (`Spec -> Код -> QA Границы -> Сверка/Фикс -> Приёмка -> Push`) отражали софтверную воронку, но требовали адаптивности для других типов ригов.

Для того чтобы Command Deck стал универсальным инструментом экосистемы OpenRig (пакетом `@openrig/deck`), способным работать с любым ригом (`kernel`, `core-platform`, `payment-gateway` или произвольным пользовательским ригом), необходимо полностью отвязать ядро от частных конвенций.

## Архитектурное Решение

### 1. Двухуровневый Dynamic Seat Guidance Provider
В `server.mjs` внедряется динамический резолвер руководств агентов (`resolveSeatGuidance`):
* **Уровень 1 (Манифест рига и AGENTS.md):** При подключении узла сервер сканирует рабочую директорию рига на наличие `AGENTS.md` или `CULTURE.md`. Сервер парсит разделы `## Обязанности` / `## Границы и запреты` и связывает их с сессией агента.
* **Уровень 2 (Адаптивный фолбэк по роли):** Если файл отсутствует или сиденье новое, руководство вычисляется автоматически по канонической роли OpenRig:
  * `orchestrator` / `owner` — координация, приёмка, ведение очереди, декомпозиция.
  * `implementer` / `coder` — реализация, локальные тесты, передача на проверку.
  * `qa` / `check` — независимая верификация, негативный контроль, проверка границ.
  * `operator` — мониторинг здоровья, вачдог контекста, триаж.
* Существующие детальные правила `core-platform` сохраняются в виде встроенного профиля по умолчанию, обеспечивая 100% обратную совместимость.

### 2. Динамические пулы моделей (Self-Discovered Model Reservoirs)
Статическая разметка контейнера `#reservoirsContainer` в `index.html` заменяется на динамический рендеринг:
* Фронтенд анализирует актуальный массив `AGENTS` и группирует узлы по семейству модели (`liveNode.modelObservation.model` или `agent.harness`):
  * **GPT / Codex Pool** (purple: `#a855f7`) — модели `gpt-6.1`, `codex`, `sol`, `terra`.
  * **Claude Pool** (amber: `#f59e0b`) — модели `claude-3-7`, `claude-code`, `sonnet`.
  * **Open-Weights / Fast Pool** (emerald: `#00ff9d`) — модели `glm`, `deepseek`, `pi`.
  * **Gemini / Frontier Pool** (cyan: `#00f0ff`) — модели `gemini`, `argon`, `agy`.
* Для каждого обнаруженного пула вычисляется:
  * Количество активных сидений (`N SEATS`, `N ACTIVE`).
  * Пиковый нагрев контекста среди узлов пула.
  * Средняя загрузка пула.
* Если в риге используется всего 1 или 2 семейства моделей, отображаются только фактически задействованные пулы.

### 3. Отказоустойчивый поиск истории и решений
* `DECISIONS_DIR` настраивается через переменную окружения `OPENRIG_DECISIONS_DIR` или относительный путь `<rig_workspace>/decisions`.
* При отсутствии каталога решений или файлов TSV сервер и фронтенд грациозно деградируют: панель отображает информативную заглушку «Журнал решений пуст», не прерывая работу телеметрии.

### 4. Автономный пакет `@openrig/deck`
* В корне проекта создается декларативный `package.json` с секцией `"bin": { "openrig-deck": "./server.mjs" }`.
* Сохраняется принцип **Zero External Dependencies**: зависимости `dependencies: {}` пусты, используются только встроенные модули Node.js 18+.

## Последствия (Consequences)

### Положительные (Positive)
1. **100% Plug-and-Play:** Любой риг экосистемы OpenRig может быть подключен к Command Deck без изменения единой строчки кода.
2. **Нулевой порог внедрения:** Никаких тяжелых npm-пакетов, компиляторов и шагов сборки; запуск за 1 секунду.
3. **Самоадаптация к модельному ряду:** При смене моделей агентов (например, переход с GPT на Claude или DeepSeek) шапка дашборда автоматически перестраивает пулы квот.
4. **Обратная совместимость:** Существующий богатый профиль `core-platform` продолжает работать в полной мере.

### Риски и нейтральные последствия
* При динамическом парсинге `AGENTS.md` заголовки могут отличаться по формату (Markdown h2 vs h3). Решается гибкими регулярными выражениями парсера с поддержкой русского и английского языков.

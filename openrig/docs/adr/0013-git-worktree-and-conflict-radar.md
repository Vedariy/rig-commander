# ADR-0013: Радар Git Worktree, кросс-конфликтов и Read-Only Diff

- **Статус:** `[ACCEPTED]`
- **Дата:** 2026-11-25
- **Связанные документы:** [ADR-0001](0001-pure-vanilla-svg-architecture.md), [ADR-0002](0002-three-tier-telemetry-bridge.md)

---

## 1. Контекст и проблема

В многоагентной разработке OpenRig и универсальных терминальных сессиях (Claude Code, Codex CLI, Pi, AGY) агенты работают параллельно в разных **linked git worktrees**, отдельных **клонах одного репозитория** или делят **общий checkout** (`cwd`). До этого момента RigCommander видел процессы, очереди `qitem` и контекстные окна, но был слеп к **уровню кода**:

1. **Скрытые merge-конфликты:** два кодера в разных worktree или отдельных клонах редактируют один и тот же файл одновременно — оператор узнаёт об этом слишком поздно, на этапе сборки или merge.
2. **Гонка в общем checkout:** 2+ активных агента одновременно пишут в один `cwd` и перезаписывают изменения друг друга.
3. **Незамеченный дрейф от upstream:** агент работает в worktree на `20–60+` коммитов позади `origin/dev`, накапливая тяжёлый rebase.
4. **Неразрешённые `unmerged` конфликты в индексе:** процесс застрял на конфликтных маркерах без явной подсветки на верхнем уровне.
5. **Ограничения безопасности и производительности:** любые git-запросы не должны блокировать `index.lock` живых агентов, не должны тормозить steady-state `/api/telemetry` (`~7–15 ms`) и не должны допускать утечку секретов (`.env*`, ключи, токены) или path traversal при просмотре diff.

---

## 2. Рассмотренные альтернативы

1. **Опрос только по `--git-common-dir`:**
   - *Минус:* не связывает два отдельных клона одного репозитория (например, основная рабочая копия + изолированный клон другого кодера). На реальном флоте зафиксированы оба паттерна одновременно.
2. **Запускать `git status` на каждый запрос `/api/telemetry` синхронно:**
   - *Минус:* проба `9` уникальных `cwd` занимает `~150–300 ms`, что разрушило бы достигнутую SWR-латентность `~7–15 ms` и нагружало диск при нескольких вкладках.
3. **Стримить полный текст `git diff` прямо в `/api/telemetry`:**
   - *Минус:* раздувание JSON-трафика на мегабайты и риск попадания чувствительных фрагментов в фоновый поток телеметрии.

---

## 3. Принятое решение

Реализована трёхуровневая (L1 / L2 / L3) система **Git / Worktree & Conflict Radar** со строгими границами безопасности и нулевой деградацией производительности:

1. **Чистый zero-DOM доменный модуль (`openrig/assets/domain/git-radar.js`):**
   - Парсинг `git status --porcelain=v2 --branch` (ветка, `oid`, `ahead/behind`, detached, tracked, renamed, unmerged `u`, untracked `?`) и `git diff --numstat` (unstaged + staged).
   - `normalizeRepoKey(originUrl, commonDir, topLevel)` унифицирует SSH и HTTPS URL (`git@host:org/repo.git` ≡ `https://host/org/repo`), благодаря чему **linked worktrees и отдельные клоны одного репо объединяются в один `repoKey`**.
   - `analyzeFleetGitRadar(workspaces, seatStateById)` строит сводку `workspaces`, карту `bySeatId`, список кросс-пересечений файлов `conflicts` (P1, если оба сиденья активны, иначе P2), `sharedWriteHazards` (2+ активных сиденья в одном checkout), `unmergedWorkspaces` и `staleWorkspaces` (`behind >= 15` warn / `>= 20` finding).

2. **Read-only SWR-коллектор и ленивый diff (`openrig/lib/git-radar.mjs` + `openrig/server.mjs`):**
   - Все git-команды выполняются с жёсткими флагами `--no-optional-locks -c core.fsmonitor=false`, таймаутом `4000 ms` и ограниченным параллелизмом (`concurrency = 3`), с дедупликацией по уникальному `cwd` и слиянием подкаталогов по `topLevel`.
   - Абсолютные локальные пути (`topLevel`, `commonDir`, `originUrl`) **удаляются** перед выходом за границу бэкенда; наружу уходит только безопасный `dirName`, `repoKey` и относительные пути файлов.
   - В `server.mjs` добавлен 12-секундный SWR + single-flight кэш (`getGitRadarCached`) и инкрементальный ревизионный ключ `gitRadarRev` (`?gitRadarRev=...` ➔ `gitRadarUnchanged: true`), сохраняющий steady-state `/api/telemetry` на уровне ~7–15 ms и 0 ms блокировки.
   - Эндпоинт `GET /api/git/diff?seat=<seatId>&file=<optionalRelPath>` (5s кэш) **никогда не доверяет путям из query** — `cwd` берётся строго из `latestFleetSnapshot.nodes`, относительный путь валидируется на отсутствие `..`, `\0`, абсолютного пути и ведущего `-`, чувствительные файлы (`.env*`, `*.pem`, `*.key`, credentials) блокируются, объём ограничен `40 KB`, а текст прогоняется через `stripAnsiAndRedact(..., { redactPaths: true })`.

3. **Fleet Intelligence Detector #7 (`openrig/lib/fleet-intelligence/detectors/git-conflict.mjs`):**
   - `GitConflictDetector` автоматически публикует находки: `P0` для unmerged-конфликтов, `P1/P2` для пересечений файлов между worktree/клонами, `P2` для конкурентной записи в общий checkout и `P2` для сильного отставания от upstream (`behind >= 20`), с прямым действием `open_git_diff` (`📄 Diff`).

4. **Прогрессивное раскрытие UI (ISO 11064 Dark Cockpit):**
   - **L1 (Граф):** чистые узлы не перегружаются — бейдж `⚔️ N` (или `🚨 M`) появляется в `.node-meta-row` **только** при наличии конфликта файлов или unmerged-индекса.
   - **L2 (Инспектор `#inspGitWorktree`):** ветка/detached, `↑ahead ↓behind`, тип копии (`worktree` / `общий ×N` / `репо`), `+ins/-del`, кликабельные чипы изменённых файлов и баннер конфликтов.
   - **L3 (`#gitDiffModal` + вкладка `🌿 Worktrees` в Советнике флота):** цветной read-only просмотр diff с фильтрацией по файлу и заметками о маскировании секретов / обрезке, а также сводная таблица всех worktree и пересечений флота (`/demo?track=git`).

---

## 4. Последствия

- **Плюсы:**
  - Оператор и Fleet Intelligence видят реальные файловые коллизии между агентами **до** merge-катастрофы.
  - Нулевая деградация latency `/api/telemetry`, нулевые npm-зависимости, 100% EN/RU паритет.
  - Безопасность по умолчанию: read-only `--no-optional-locks`, запрет чтения произвольных путей и `.env`, автоматическое маскирование секретов.
- **Ограничения:**
  - Информация об `ahead/behind` отражает локальные tracking refs (бэкенд намеренно не выполняет сетевой `git fetch`).
  - Untracked-файлы отображаются в списке изменений и участвуют в детекции пересечений, но их содержимое не считывается через `/api/git/diff` ради защиты от утечек.

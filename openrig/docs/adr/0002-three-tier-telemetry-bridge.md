# ADR-0002: Трёхзвенный мост телеметрии (`server.mjs`)

- **Статус:** `[ACCEPTED]`
- **Дата:** 2026-11-04
- **Контекст:** Интеграция браузерного дашборда с демоном OpenRig, очередью `rig queue` и буферами сессий `tmux`.

---

## 1. Контекст и проблема

Браузерная песочница по соображениям безопасности не имеет доступа к локальной файловой системе хоста, сокетам `tmux` и возможности исполнять CLI-утилиты (`rig queue list`, `rig capture`, `rig parked`).

При этом демон OpenRig (`http://127.0.0.1:7437`) предоставляет HTTP API для чтения узлов (`/api/rigs/:id/nodes`), но:
1. Не агрегирует исторический трафик очередей между парами агентов;
2. Не отдаёт сырой буфер экрана терминала `tmux`;
3. Не выполняет предиктивный расчёт аналитики качества возвратов QA;
4. Требует авторизованных CORS-заголовков для доступа из браузера.

## 2. Принятое решение

Создать выделенный легковесный локальный сервис **`server.mjs`** на встроенном модуле `node:http` (порт `7440`), реализующий **трёхзвенную архитектуру синхронизации**:

```
[ Браузер: index.html ]
         │
         ▼ (HTTP JSON каждые 4с)
[ Сервер телеметрии: server.mjs (:7440) ]
   ├──> 1. OpenRig Daemon API (:7437) — live contextUsage, activityState, model
   ├──> 2. CLI rig queue list -A — активные строки и история вызовов
   ├──> 3. CLI rig parked — диагностика зависших обязательств
   ├──> 4. Файлы decisions/*.tsv — журнал суждений и решений
   ├──> 5. Файлы seats/*/recap-superseded/ — реальное число автосжатий/свапов
   └──> 6. CLI rig capture / tmux — живой снимок экрана терминала
```

### Реализованные эндпоинты:
- **`GET /api/telemetry`**: Параллельный сбор (`Promise.all`) состояния ригов (`core-platform` и `kernel`), парсинг очередей, вычисление трафика `nodeTraffic` (in/out) и аналитики возвратов кодеров.
- **`GET /api/capture?seat=<id>&lines=<n>`**: Захват последних N строк терминала агента через `rig capture` для отображения в мини-терминале паспорта.
- **`POST /api/send`**: Безопасная отправка пользовательского ввода или управляющих команд в терминал агента (`rig send`).

## 3. Последствия

### Плюсы:
- Браузер освобождён от сложного парсинга CLI и тяжёлой нормализации данных;
- Изоляция сетевых вызовов: сервер кэширует тяжёлые исторические выборки на 20 секунд, защищая демон OpenRig от спама;
- Сервер написан на чистом нативном Node.js (ESM), без единой сторонней зависимости (`node:http`, `node:fs`, `node:child_process`).

### Минусы и ограничения:
- Для работы живого режима требуется, чтобы процесс `node server.mjs` был запущен в фоне (в Snapshot Mode дашборд работает автономно по замороженному снимку).

# ADR-0008: Harness-Aware Command Dispatching & Terminal Prompt Hygiene

## Статус
Принято (Accepted)

## Контекст и Проблематика
Мультиагентная экосистема OpenRig объединяет агентов, функционирующих на существенно различающихся интерактивных харнесах:
1. **Codex CLI (OpenAI / GPT-6 / Sol):** Полноценная поддержка нативных слэш-команд в строке ввода (`/compact`, `/new`, `/model`).
2. **Claude Code CLI (Anthropic):** Поддержка встроенных слэш-команд (`/compact`, `/clear`, `/cost`), а также интерактивных ответов меню (`1`, `2`, `y`, `n`).
3. **Pi CLI (DeepSeek-flash / open-weights):** Харнес прямого диалога, **не поддерживающий** слэш-команды readline. Отправка команды вроде `/compact` передается в языковую модель как обычный текст пользователя, засоряя контекст бессмысленным промптом и сбивая ход решения. Для Pi правильной операцией компактификации является ротация сессии (`rig restart <seat>`).
4. **Antigravity CLI (AGY / Google):** Поддерживает слэш-команды управления (`/compact`, `/clear`, `/effort`, `/model`).

### Проблема загрязнения строкового буфера (`/compact/compact`)
При отправке быстрых действий или ручном вводе через веб-интерфейс дашборда команды передаются в активную tmux-сессию через `tmux send-keys -t seat -l text`.

Если в терминале агента уже находился префикс (например, оператор случайно нажал `/`, терминал завис на автокомплите, или кнопка была нажата повторно), tmux производил конкатенацию символов в текущую позицию курсора. В результате в терминал отправлялись мусорные последовательности вида:
* `/compact/compact`
* `//compact`
* `/clear/clear`

Харнес отклонял такие команды как синтаксически неверные либо зависал, требуя ручного вмешательства через отдельный терминал.

---

## Архитектурное Решение

### 1. Протокол очистки строки терминала (Line Hygiene via `C-u`)
В обработчик `/api/send` сервера `server.mjs` (при типе команды `type === 'raw'`) внедрена обязательная фаза предварительной очистки буфера readline:
```javascript
// Отправка Unix readline clear-to-beginning (C-u) перед передачей команды:
await safeTextExec(TMUX_BIN, ['send-keys', '-t', seat, 'C-u']);
await safeTextExec(TMUX_BIN, ['send-keys', '-t', seat, '-l', cleanText]);
await safeTextExec(TMUX_BIN, ['send-keys', '-t', seat, 'Enter']);
```
Это гарантирует, что независимо от состояния курсора или висящих в строке символов ввод всегда начинается с чистой строки.

### 2. Дедупликация и нормализация токенов
И на клиенте (`submitAgentPrompt`), и на сервере (`/api/send`) внедрена защита от случайного дублирования слэш-команд:
```javascript
cleanText = cleanText.replace(/(\/[a-zA-Z0-9_-]+)\1+/g, '$1');
```
Последовательности вида `/compact/compact` или `/clear/clear` автоматически нормализуются в `/compact` и `/clear` до отправки в сессию.

### 3. Динамическая клавиатура быстрого ввода под харнес (`renderHarnessQuickKeys`)
Панель быстрого ввода терминала (в инспекторе узла и в модальном окне на 80 строк) теперь динамически определяет харнес выбранного агента и формирует адаптированный набор кнопок:
* **Codex:** `✅ 1 (Proceed)`, `y (Yes)`, `❌ Esc`, `🛑 Ctrl+C`, `⚡ /compact`, `🆕 /new`, `⏎ Enter`.
* **Claude Code:** `✅ 1 (Proceed)`, `y (Yes)`, `❌ Esc`, `🛑 Ctrl+C`, `⚡ /compact`, `🧹 /clear`, `💰 /cost`, `⏎ Enter`.
* **Pi (DeepSeek):** `⏎ Enter`, `y (Yes)`, `❌ Esc`, `🛑 Ctrl+C`, `🚫 /compact` (заблокирована с подсказкой о ротации сессии).
* **AGY (Antigravity):** `✅ 1 (Proceed)`, `❌ Esc`, `🛑 Ctrl+C`, `⚡ /compact`, `⚙️ /effort`, `⏎ Enter`.

### 4. Защитный барьер для неподдерживаемых харнесов (Harness Safety Guard)
* В `/api/send` запросы `/compact` в сторону агентов с харнесом `pi` блокируются сервером со статусом HTTP 400 и понятным сообщением:
  > *«Харнес Pi (DeepSeek) не поддерживает команду /compact. Используйте ротацию сиденья.»*
* В полосе триажа (`renderTriageStrip`) при превышении порога контекста 65% для узлов на базе Pi кнопка действия автоматически меняется на `🔄 Ротация` (`rig restart <seat>`), а для Codex/Claude/AGY — на `⚡ /compact`.

## Последствия (Consequences)

### Положительные (Positive)
1. **Исключение повреждения промптов:** Никаких случайных склеек `/compact/compact` или замусоривания readline.
2. **Безопасность для Open-Weights моделей:** Pi/DeepSeek защищены от попадания служебных команд в контекст рассуждений.
3. **Опережающая обратная связь:** Оператор видит актуальный и применимый именно к этому агенту набор управляющих клавиш.
4. **Консистентность интерфейса:** Панель инспектора и модальное окно полноэкранного терминала используют общий проверенный генератор кнопок `renderHarnessQuickKeys`.

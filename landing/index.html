4–8 PARALLEL AGENTS IN TMUX

Why Multi-Agent Terminal Sessions Break Down

One AI agent in your editor feels effortless. Once 4–8 parallel sessions run across separate tmux panes and worktrees, blocked prompts, context drift, and spend disappear into a black box.

✕ Without RigCommander: Chaos
  • • Blind Terminal Hopping: Scrambling through 12 detached tmux panes trying to figure out which agent is blocked or waiting in queue.
  • • Silent Permission Hangs: An agent sits idle for 4 hours waiting for a numbered confirmation prompt you never saw.
  • • Circular Rework Loops: QA rejects coder's PR 5 times in a loop, burning 300,000 tokens without anyone noticing wait bottlenecks.
  • • Blind Token Spend & Unverified Commands: No visibility into per-seat `$` burn, cache-hit rates, or whether `/compact` actually reduced context.
✓ With RigCommander: Deterministic Control
  • • One Live Map for Every Agent: Auto-discover parallel Claude Code, Codex CLI, Gemini CLI & tmux sessions, then flip between live graph and task timeline (G) to spot waits and rework loops.
  • • 1-Click Terminal HITL with Safety Guards: Read the live tmux prompt and parsed approval options before clicking; quick-action buttons dispatch strictly allowlisted control keys (optional manual input requires explicit typing + confirmation), deduplicated and verified after send.
  • • Proactive Context & Spend Guardrails: Catch overheating sessions (≥75% context) with 1-click /compact, flag repeating QA loops, and cap token burn with a local circuit-breaker.
  • • Local-First Cost Clarity & Zero-Write Start: Compare subscription usage (SUB) vs estimated API spend (PAYG), evaluate safely with --read-only, and keep all logs on your machine.

Operator FAQВопросы оператора

How do I start the live deck?Как запустить живой пульт?

Run npx rig-commander@{{APP_VERSION}} --read-only with Node.js 18 or later, then open http://127.0.0.1:7440.

С Node.js версии 18 или новее выполните npx rig-commander@{{APP_VERSION}} --read-only и откройте http://127.0.0.1:7440.

Can I try it without running agents?Можно попробовать без запущенных агентов?

Yes. The offline demo uses sample fleet data and makes no live fleet API calls.

Да. В демо используются примеры данных без обращений к API живого флота.

Do I need OpenRig?Обязательно ли устанавливать OpenRig?

OpenRig provides fleet and queue context. Universal discovery also finds supported local tmux sessions.

OpenRig предоставляет сведения о флоте и очереди. В универсальном режиме пульт также находит поддерживаемые локальные сессии tmux.

Where can I trace a handoff?Где посмотреть передачу задачи?

Select the task in the Gantt timeline to inspect its waiting time, destination and recorded handoff references.

Выберите задачу на диаграмме Ганта: там видны время ожидания, получатель и ссылки на передачу.

Who approves terminal actions?Кто подтверждает действия в терминале?

The operator reviews the prompt and chooses a response. The Fleet Advisor provides recommendations.

Оператор читает запрос и выбирает ответ. Советник флота даёт рекомендации.

Does recovery restart my fleet automatically?Восстановление автоматически перезапускает флот?

Recovery requires a plan preview and explicit confirmation. Check the receipt for restored, partial, failed or unknown results.

Для запуска нужно просмотреть и подтвердить план. В отчёте указывается результат: полное или частичное восстановление, ошибка либо неизвестный исход.

Is the local recovery vault encrypted?Зашифровано ли локальное хранилище восстановления?

The local vault stores plaintext files with owner-only permissions.

Данные в нём хранятся без шифрования в файлах, доступных только владельцу.
